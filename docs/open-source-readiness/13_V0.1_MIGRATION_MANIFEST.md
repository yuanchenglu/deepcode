# DeepCode v0.1 迁移与删除清单

> 状态：Phase 0 已确认
> 原则：先建立统一替代路径和回归测试，再删除重复实现

## 1. 目的

本清单用于控制 Runtime、Built-in DeepAgent、Gateway 和 Harness 的迁移范围，避免：

- 在没有替代路径时直接删除代码。
- 同一能力长期维护两套实现。
- 迁移过程中扩大产品范围。
- 把“保留源码”误写成“正式支持”。

状态：

- **Keep**：保留并继续维护。
- **Integrate**：接入统一 Runtime。
- **Replace**：由新实现替换。
- **Delete after migration**：替代路径和测试完成后删除。
- **Archive**：只保留历史参考。
- **Verify**：先扫描实际代码再判定。

## 2. Package 级定位

| 区域 | 当前用途 | v0.1 目标 | 动作 |
|---|---|---|---|
| `packages/core` | Session、Harness、Permission 等 | 统一 Runtime 核心 | Keep / Refactor |
| `packages/opencode` | CLI/TUI 与主入口 | DeepCode 正式入口 | Keep / Integrate |
| `packages/llm` | Provider Protocol | DeepSeek Contract 真相源 | Keep / Fix |
| `packages/oh-my-deepagent` | Role、Skill、可能含独立 Runtime | 内置 Agent 能力包 | Integrate / Delete duplicate runtime |
| `packages/deepcode-gateway` | Gateway Core 和 Adapters | 正式 Gateway | Refactor / Integrate |
| Desktop/Web 等 | 上游 UI | 非 Phase 0 核心改造 | Keep / Verify |
| 旧 docs / 众测产物 | 历史设计与参考 | 非现状依据 | Archive |

实际路径和符号必须在 Phase 1 扫描后补充，不允许按文件名猜测后删除。

## 3. Built-in DeepAgent 清单

### Keep

- RoleDefinition 类型和角色文件。
- 13 Role Registry。
- SkillDefinition 和 Skill Registry。
- Role Prompt。
- Agent Policy。
- Role/Skill 单元测试和 Fixtures。
- 角色名称回归测试。

### Integrate

- Role Selection → DeepCode Session。
- Role Prompt → Context Projector。
- Role Tools → Unified Tool Executor。
- Role Skills → Skill Resolver。
- Role Events → Runtime Events。
- Agent UX Metadata → CLI/TUI/Gateway。

### Delete after migration

以下内容若实际存在，完成替代后删除：

- 独立 Message Loop。
- 独立 Session Store。
- 独立 Provider Invocation。
- 独立 Tool Executor。
- 独立 Permission Engine。
- 独立 Memory / History Store。
- 独立 CLI / Server 入口。
- 与 DeepCode Runtime 重复的 Abort、Settlement、Usage 逻辑。

### Verify

Phase 1 必须输出：

- 准确 13 角色文件清单。
- 所有 Role Tools 和 Skills 引用。
- 独立 Runtime 符号和调用入口。
- Package export 和依赖图。
- 当前测试可执行性。

## 4. Gateway 清单

### Keep

- Platform Adapter 源码。
- 平台 Parser 和 Fixtures。
- 平台 API Client。
- 飞书官方 SDK 或经验证的纯 TypeScript 实现。
- Gateway Error 和 Message 类型中可复用部分。

### Replace

- 通用无鉴权 Router → Adapter `verifyInbound` + Core Middleware。
- 单消息 Parser Contract → 批量 Message Contract。
- chatId-only Session → 多维 Session Key。
- 单 Adapter Consumer → sourceAdapter 路由。
- 无界 Queue → 有界 Queue。
- 非原子 Idempotency → TTL Store。
- 不完整 Timeout → Abort + kill escalation。

### Integrate

- Gateway Consumer → `DeepCodeRuntime.prompt()`。
- Gateway Session → Session Service。
- Gateway Permission → Unified Permission。
- Gateway Role Selection → Role Registry。
- Gateway Evidence → Runtime / Delivery Events。

### Delete after migration

- 每条消息启动 CLI 子进程的正式路径。
- 固定使用 `adapters.values().next()` 回包的逻辑。
- 无鉴权直接 `Queue.offer` 的路径。
- 只用 `chatId` 的 Session Map。
- 无界 Queue。
- 已废弃飞书 WebSocket/桥接方案。
- 与 Runtime 重复的 Agent Loop。

### Archive

- 已废弃 Gateway 设计文档。
- 与当前目录结构不一致的旧架构说明。
- 失效截图和不可复现验证记录。

## 5. Runtime 清单

### Keep

- OpenCode V2 Session 和 Provider 主链路。
- Message、Tool、Reasoning 的规范化 Schema。
- Tool Settlement。
- Permission 基础能力。
- Compaction 和 History Projection 基础。

### Refactor / Integrate

- 暴露内部 `DeepCodeRuntime` API。
- SessionRunner 拆分编排和 Policy。
- Model Routing 前置。
- Reasoning Policy 接入 History Projection。
- Harness Decisions 增加 applied 状态。
- 统一 Tool Executor。

### Replace

- Workflow `deny` 被预批准的逻辑。
- 路径字符串前缀判断。
- Scope fail-open。
- Role/Skill Tool 未过滤。
- Harness 仅日志不消费却标记成功的逻辑。

## 6. Harness 清单

### Keep

14 个模块的研究成果和可复用实现。

### Integrate First

- Model Router。
- Hard Constraints。
- Reasoning Manager。
- Intent Router。
- Scope Guard。
- Context Window Manager。
- Review / Immune。

### Integrate Progressively

- OKR Plan。
- Review Anti-drift。
- Memory Granularity。
- Meta Directives。
- Signal Tagger。
- Skill Evolution。

### Rules

- 有 Service/Node 不等于已接入。
- 有调用不等于输出已消费。
- 有日志不等于 Enforcement。
- 每个模块必须有 decided/applied/test/evidence。

## 8. 删除门槛

任何生产代码删除必须满足：

1. 已识别所有调用方。
2. 新路径已实现。
3. 迁移测试通过。
4. 关键行为 E2E 通过。
5. 没有配置仍引用旧入口。
6. 文档和示例已更新。
7. 回滚方案明确。
8. Commit 或 PR 中引用对应 Manifest 条目。

## 10. 迁移顺序

```text
MIG-0 Accurate inventory
→ MIG-1 Runtime API
→ MIG-2 Agent Role/Skill integration
→ MIG-3 Unified Tool/Permission
→ MIG-4 Gateway Runtime Bridge
→ MIG-5 Adapter security/session
→ MIG-6 Harness applied behavior
→ MIG-7 Remove duplicate implementations
→ MIG-8 Release cleanup
```

## 11. 明确禁止

- 在统一 Runtime API 前删除旧 Agent Loop。
- 在 Gateway Runtime Bridge 前删除所有兼容路径。
- 因测试难补而删除已确认的 Gateway 或角色目标。
- 保留两套 Runtime 并以“暂时”名义进入正式发布。
- 仅根据 Commit Message 判断迁移已完成。
- 未扫描调用方就批量移动或删除 Package。

## 12. 完成条件

- Package 职责与架构文档一致。
- 所有入口使用同一 Runtime。
- 13 角色只保留一套执行链。
- Gateway 只保留一套 Session 和 Runtime Bridge。
- 旧实现均有删除证据和回归测试。
- 仓库不存在仍被默认加载的 Deprecated 入口。
