# DeepCode v0.1 Built-in DeepAgent 集成计划

> 状态：Phase 0 已确认
> 核心目标：13 个角色正式预装，但不维护第二套生产 Runtime

## 1. 集成目标

将 `packages/oh-my-deepagent` 从“可能独立运行的 Agent 包”收敛为 DeepCode 内置 Agent 能力包。

最终形态：

```text
DeepCode Installation
└── Built-in DeepAgent
    ├── Role Registry
    ├── Skill Registry
    ├── Role Policy
    ├── Role UX Metadata
    └── Agent Tests
```

不再存在：

```text
oh-my-deepagent Product
├── 独立 CLI
├── 独立 Session
├── 独立 Tool Loop
├── 独立 Permission
└── 独立 Provider Runtime
```

## 2. 正式发布标准

一个 Role 达到 Stable 必须具备：

1. Role ID 唯一且命名稳定。
2. Display Name、Description、适用场景明确。
3. System Prompt 完整，无无效占位符。
4. Tool 白名单真实执行。
5. Skill 依赖可解析且冲突可检测。
6. 使用统一 Permission。
7. 使用统一 Session 和 Context。
8. 用户可在 UI 或命令中选择。
9. 单元测试通过。
10. Runtime 场景测试通过。
11. 不得访问白名单外 Tool。
12. 文档说明输入、输出、限制和风险。

## 3. 角色分层

### 核心角色

- Build
- Plan
- Review

要求：正式一级入口、完整 E2E、默认文档重点介绍。

### 高级角色

仓库现有其他 10 个角色全部预装，通过角色选择器访问。

已知新增角色包括：

- Oracle
- Metis
- Momus
- Multimodal
- Artistry

其他现有角色在 Phase 1 扫描后生成准确清单，不以记忆补全名称。

## 4. 角色注册模型

建议统一为：

```ts
interface RoleDefinition {
  id: string
  displayName: string
  description: string
  systemPrompt: string
  tools: readonly ToolName[]
  skills: readonly SkillName[]
  risk: RiskLevel
  maturity: Maturity
  defaultModelPolicy?: ModelPolicy
  permissionProfile?: PermissionProfile
  scenarios: readonly ScenarioId[]
}
```

Role Registry 负责：

- 注册和唯一性验证。
- 查询和搜索。
- 默认 Role。
- 成熟度和 UI 排序。
- Tool / Skill 引用完整性验证。

Role Registry 不负责：

- 自行执行 Tool。
- 自行调用 Provider。
- 自行持久化 Session。

## 5. Role Runtime 集成

### 5.1 选择

入口可以提供 `roleId`：

- CLI/TUI 用户显式选择。
- Gateway 命令或会话配置选择。
- 没有选择时默认 Build。

### 5.2 应用

```text
requested role
→ Role Registry resolve
→ Role Policy validate
→ role.decided event
→ Context Projector apply prompt
→ Tool Executor apply whitelist
→ role.applied event
```

只有产生 `role.applied` 才算角色已生效。

### 5.3 切换

- 角色切换发生在同一 Session。
- 记录旧 Role、新 Role、原因和发起方。
- 不复制整个 Session。
- 不继承不匹配的临时 Permission Approval。
- 切换失败时继续使用原 Role，并明确原因。

## 6. Tool 白名单

真实暴露 Tool：

```text
Global Registry
∩ Role Tools
∩ Loaded Skill Tools
∩ User Permission
∩ Workspace Capability
∩ Entry Capability
```

### 安全规则

- Role 未声明的 Tool 不提供给模型。
- 即使 Role 声明 Tool，Permission deny 仍优先。
- Gateway 入口可进一步限制 Tool。
- Skill 不得扩张出 Role 和 Permission 允许范围。
- Shell 不因 Role 是高级角色而自动允许。

## 7. Skill 集成

### SkillDefinition

- name
- description
- prompt/context
- tools
- dependencies
- conflicts
- source
- maturity

### 加载流程

```text
Role.skills
→ Skill Registry resolve
→ dependency/conflict validation
→ Context Projection
→ Tool intersection
```

### v0.1 边界

- 允许预装 Skill。
- 允许用户加载经过授权的 Workspace Skill。
- Skill Evolution 只允许提出建议或生成草稿。
- 不自动修改或启用全局 Skill。

## 8. Agent 协作模式

### 正式支持

- 用户显式角色切换。
- Plan → Build → Review 顺序协作。
- 同 Session、同 Task、同 Workspace。
- 每个角色拥有独立事件和证据。

### Beta

- 根据 Intent 推荐角色。
- Review 触发 Build 修复。
- Plan 输出 expected files 并初始化 Scope。

### v0.1 非目标

- 无监督并行 Multi-Agent 写操作。
- 多角色争论后自动执行高风险决策。
- 动态创建角色并立即启用。

## 10. 测试计划

### Registry Tests

- 13 个 ID 唯一。
- Role 名称回归。
- Tool 引用存在。
- Skill 引用存在。
- 默认 Role 存在。

### Policy Tests

- 白名单外 Tool 不可见。
- deny 优先。
- Skill 不扩权。
- Gateway Profile 进一步收缩权限。

### Runtime Scenarios

每个 Role 至少一个：

- 输入任务。
- 验证 Role Prompt 已应用。
- 验证预期 Tool 可见。
- 验证禁止 Tool 不可见。
- 验证输出满足角色契约。
- 验证 Session 历史和 Evidence。

### 协作 E2E

- Plan → Build。
- Build → Review。
- Review → Build 修正。
- Gateway 选择 Role 并继续同一 Session。

## 11. 迁移步骤

### A1 资产盘点

- 生成 13 Role 准确清单。
- 盘点 Skill。
- 盘点独立 Runtime 代码。
- 标记保留、迁移、删除。

### A2 定义 Runtime Role Contract

- RoleDefinition。
- Role Registry Adapter。
- Role events。
- Role selection config。

### A3 接入 Context

- Role Prompt 进入 Context Projector。
- 切换产生动态 Context Update。

### A4 接入 Unified Tool Executor

- 实现 Tool 交集。
- 移除角色自己的 Tool 执行路径。

### A5 接入 Skill

- 依赖和冲突检查。
- Context 和 Tool 交集。

### A6 删除第二套 Runtime

只有在测试覆盖后删除：

- Message Loop。
- Session Store。
- Provider 调用。
- Tool Executor。
- Permission。
- Memory Runtime。
- 独立 CLI。

### A7 发布与文档

- 角色选择说明。
- 每个角色说明页。
- 成熟度标签。
- 扩展 Role/Skill 指南。

## 12. 退出条件

1. 13 个角色全部出现在内置 Registry。
2. DeepCode 安装后无需另装 Agent 包。
3. 不存在第二套生产 Session 和 Tool Loop。
4. Role Tool 白名单真实执行。
5. Role/Skill 不能绕过 Permission。
6. 核心角色 E2E 全通过。
7. 高级角色均有自动化场景测试；未达到 Stable 的必须明确标 Beta 且功能可用。
8. Gateway 可以选择和保持 Role。
9. 文档和 README 不再将 oh-my-deepagent 描述为独立产品。
