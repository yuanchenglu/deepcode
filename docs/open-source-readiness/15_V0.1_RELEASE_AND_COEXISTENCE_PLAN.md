## 1. 当前结论

1. 当前发布结论为 **NO-GO**。
2. 官网和根 README 的 `npm install -g deepcode` 不属于本项目的有效安装方式；在本项目拥有可信制品前不得公开展示。
3. v0.1 采用 **CLI-first Alpha**：先交付独立、可安装、可完成最小 DeepSeek 编码任务的 CLI。
4. `oh-my-deepagent` 全量角色编排、Gateway Stable、飞书 Stable 和桌面版不再阻塞 v0.1 Alpha；分别进入后续里程碑。
5. 安装、发行身份、OpenCode 共存和 CI 从末期工作前移为首批 P0。
6. 架构图中的 Built-in Plugin 和 Gateway 关系是目标架构，不代表当前生产调用链已经存在。

## 2. 发布目标与版本边界

### 2.1 v0.1.0-alpha.1

交付：

- 独立的 `deepcode` CLI；
- 一种由本项目控制、经过验证的安装方式；
- DeepSeek Provider 最小任务闭环；
- 文件读取、修改、Shell 和权限确认；
- 一个默认 Coding/Build Agent；
- Session 保存、恢复和明确卸载；
- macOS 上与 OpenCode、Oh-my-OpenAgent 共存。

不交付：

- 桌面安装包；
- Gateway Stable 或飞书 Stable；
- 13 个角色全部 Stable；
- 未完成宿主契约的 Subagent/Multi-Agent 生产写入；
- npm 无作用域包 `deepcode` 或 `deepcode-ai`。

### 2.2 v0.1.0-beta.1

- macOS/Linux 安装、升级、卸载矩阵；
- Required CI、Secret/Dependency/License Scan；
- 官网公开安装；
- 外部试用和已知限制。

### 2.3 后续版本

- v0.2：正式接入 `oh-my-deepagent`，交付关键角色和编排链路；
- v0.3：Gateway Core 和飞书 Stable；
- Desktop：完成独立 App ID、协议、目录、更新源和签名后单独发布。

## 3. 发行身份契约

以下名称是默认隔离边界：

| 资源                   | DeepCode 默认值                     | 禁止默认复用                       |
| ---------------------- | ----------------------------------- | ---------------------------------- |
| CLI                    | `deepcode`                          | `opencode`、`omo`                  |
| 安装目录               | `~/.deepcode/bin`                   | `~/.opencode/bin`                  |
| 全局配置目录           | `~/.config/deepcode` 或平台等价目录 | `~/.config/opencode`               |
| 项目配置目录           | `.deepcode/`                        | `.opencode/`                       |
| 配置文件               | `deepcode.json` / `deepcode.jsonc`  | `opencode.json` / `opencode.jsonc` |
| 数据/缓存/状态命名空间 | `deepcode`                          | `opencode`                         |
| 数据库                 | `deepcode.db`                       | `opencode.db`                      |
| 环境变量               | `DEEPCODE_*`                        | `OPENCODE_*`                       |
| 临时目录前缀           | `deepcode-*`                        | `opencode-*`                       |
| Server/Gateway         | 默认关闭或 loopback；端口可配置     | 不依赖 OpenCode 固定端口           |

内部 TypeScript 包名可暂时保留上游命名，但所有用户可见、持久化和安装边界必须满足本表。

## 4. 共存契约

### 4.1 默认行为

DeepCode 默认不得：

- 读取或写入 OpenCode 的配置、数据库、缓存、日志、插件和 Session；
- 解释 `OPENCODE_*` 环境变量；
- 自动加载 `.opencode` 中的 Oh-my-OpenAgent；
- 覆盖 `opencode`、`omo` 或其他已有命令；
- 在升级或卸载时调用 OpenCode 的包管理命令；
- 删除名称中包含 `opencode` 的目录或 Shell PATH 配置。

### 4.2 显式兼容

若未来需要兼容，必须采用显式单向操作，例如：

```text
deepcode import opencode
```

该操作必须先展示来源、目标、冲突和写入清单；不得以默认回退或静默迁移实现。

### 4.3 桌面版

桌面版在以下内容全部独立前不得进入公开制品：

- App ID / Bundle ID；
- Product Name；
- URL Scheme；
- userData 和 Store Key；
- 可执行文件和安装包名称；
- 更新仓库、签名和卸载标识。

## 5. 官方安装链

### 5.1 Alpha 首选渠道

首个 Alpha 使用 GitHub Release 二进制作为唯一可信源：

```text
Tag
→ CI Build
→ Platform Archive
→ SHA-256 / SBOM / License Manifest
→ GitHub Release
→ deepcode.starseas.org/install
```

官网安装脚本必须：

- 只从本项目 Release 下载；
- 校验版本、平台和 SHA-256；
- 安装到 DeepCode 自有目录；
- 可重复执行；
- 提供对应卸载命令；
- 失败时不留下半安装状态。

### 5.2 npm

npm 不是 Alpha 的前置条件。启用前必须：

1. 确认由项目控制的 scoped package 名称；
2. 保证 wrapper、平台包、postinstall 和二进制名称一致；
3. 在干净 npm/bun/pnpm 环境执行安装和卸载 Smoke；
4. 不发布或依赖第三方 `deepcode`、`deepcode-ai`。

## 6. 关键执行顺序

### P0-A 公开信息止损

- 官网移除无效安装命令；
- 根 README 将未验证能力和安装方式降级为 Alpha 状态；
- 所有架构图标注 Current 或 Target。

退出条件：公开页面不再引导安装第三方包，不再把 Partial/Fail 能力写成 Stable。

### P0-B 发行身份与隔离

- 替换用户可见 `opencode` 标识；
- 切换配置、数据、数据库、环境变量和临时目录；
- 禁止默认发现 `.opencode`；
- 修复 upgrade/uninstall 目标；
- 增加共存自动化测试。

退出条件：DeepCode 启动、运行、升级和卸载均不读取或修改 OpenCode 状态。

### P0-C 最小运行链

- 修复 `reasoning_effort` lowering；
- 让 Model Routing 决策作用于当前 Provider Turn，或在 Alpha 中关闭该主张；
- 修复 Permission deny 进入 preapproved；
- 以 Mock Contract 和一次受控真实 DeepSeek 请求验证最小任务。

退出条件：Provider Wire Contract、Permission 回归和本地任务 E2E 通过。

### P0-D 发行流水线

- 确定唯一默认分支；
- Required CI 覆盖默认分支和 PR；
- 移除仅允许 `anomalyco/opencode` 的发布条件；
- 构建 macOS arm64/x64 和 Linux arm64/x64；
- 生成 checksum、SBOM 和许可证清单。

退出条件：同一 Commit 可由 CI 重建并生成可验证 Release。

### P0-E 开源治理

- 更新 LICENSE 归属和上游保留声明；
- 重写 SECURITY、CONTRIBUTING；
- 增加 SUPPORT、UPSTREAM、CODE_OF_CONDUCT 和第三方声明；
- 完成 Secret 历史处置和来源/许可证审计。

退出条件：报告入口属于 DeepCode；发布制品没有未解释的许可证或凭据风险。

## 7. Parallels macOS 验收矩阵

只有候选 Release 生成后才执行虚拟机验收。

| 场景   | 初始状态                   | 必测操作                          |
| ------ | -------------------------- | --------------------------------- |
| VM-001 | 干净 macOS                 | 安装、首次运行、任务、卸载        |
| VM-002 | 已安装 OpenCode            | 安装和同时运行 DeepCode           |
| VM-003 | OpenCode + Oh-my-OpenAgent | DeepCode 启动、插件发现、任务执行 |
| VM-004 | 已安装旧 DeepCode Alpha    | 升级、失败回滚、卸载              |

每个场景记录：

- `which deepcode`、`which opencode`、`which omo`；
- 安装前后 OpenCode 配置和数据库校验值；
- DeepCode 实际读取/写入目录；
- 进程、监听地址和端口；
- 安装、任务、升级、卸载日志；
- 快照名称、Release SHA 和测试结果。

通过条件：

- OpenCode/Oh-my-OpenAgent 的命令和状态不变；
- DeepCode 不自动加载 Oh-my-OpenAgent；
- 三个命令可同时存在；
- 卸载仅删除 DeepCode 文件；
- 官网命令可在干净快照完成首个任务。

## 8. Alpha Go/No-Go

只有同时满足以下条件才允许官网公开安装：

- 官网下载源属于本项目；
- 发行身份和共存契约全部通过；
- P0 安全缺陷在 Alpha 暴露面上为 0；
- Provider Contract 和最小任务 E2E 通过；
- macOS VM-001~004 通过；
- 默认分支 Required CI 全绿；
- Release 有 SHA-256、SBOM、许可证清单；
- README Claim Evidence Coverage = 100%；
- Gateway、Desktop 和未集成 Agent 能力未被误写为 Stable。

任一门禁失败，结论保持 NO-GO。

## 附录 B：Q&A 过程记录

#### Q#1：为什么 Gateway 和 13 个角色不再阻塞 v0.1 Alpha？

> 2026-07-27 | 开源与上线优先级复核 | 用户确认采用建议

**问题**：原计划要求 Gateway Core、飞书和全部角色达到正式发布标准，安装和 CI 却排在最后，无法尽早形成真实用户闭环。

**答案**：先发布隔离、安全、可安装的 CLI Alpha；插件编排和 Gateway 按独立里程碑交付。代码可以保留在开源仓库，但未集成能力不得进入默认制品或 Stable 主张。
