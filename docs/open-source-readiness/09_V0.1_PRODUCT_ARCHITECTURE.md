## 1. 产品公式

```text
DeepSeek Model
+ Isolated DeepCode CLI/Host                         [v0.1]
+ Built-in oh-my-deepagent Plugin                    [v0.2]
+ DeepCode Gateway                                   [v0.3]
+ Independent Desktop                                [later]
= DeepCode Roadmap
```

## 2. 产品不是三套互斥系统

DeepCode、oh-my-deepagent 和 Gateway 的目标关系是：

- DeepCode/OpenCode 提供宿主产品和基础执行能力；
- oh-my-deepagent 作为内置插件提供角色、技能和 Agent 编排；
- Gateway 提供消息平台入口；
- 三者通过明确契约共生，而不是互相替代。

当前只有 Host/CLI 基础和各独立 Package 代码存在；Built-in Plugin 与 Gateway 的生产调用关系尚未证明。

## 4. 两种合法循环

### 4.1 Host Execution Loop

```text
Model Request
→ Tool Call
→ Permission / Workspace Check
→ Tool Execution
→ Tool Result
→ Model Continuation
```

宿主对真实副作用、安全和正式证据负责。

### 4.2 Plugin Orchestration Loop

```text
Task Analysis
→ Role Selection
→ Plan
→ Delegate to Build/Subagent
→ Review
→ Rework or Finish
```

插件编排循环是产品能力，应当保留并正式验证。

## 5. oh-my-deepagent 的产品定位

### 5.1 v0.2 正式内置目标

- 随 DeepCode 安装。
- 不要求用户安装另一个产品。
- 角色和 Skill 可在本地与 Gateway 中选择。
- 插件支持单 Agent、Subagent 和多 Agent 编排。

### 5.2 不做预设删除

当前 Package 中的以下实现需要审计，不直接判定重复：

- AgentRuntime；
- runMessageLoop；
- ToolRunner；
- MemoryStore；
- Provider Adapter；
- InProcess/HTTP/CLI Transport。

它们可能属于生产插件实现、兼容层、测试 Runtime 或过渡代码。

### 5.3 产品约束

- 插件不能无意绕过宿主 Permission 和 Workspace Policy。
- 插件产生真实工作区副作用时必须有可审计路径。
- 插件可维护派生状态、Subagent 状态和工作记忆。
- 正式会话与插件内部会话的映射必须明确。

## 6. 用户入口

### CLI/TUI

用户可以：

- v0.1 使用一个默认 Coding/Build Agent；
- 发起本地代码任务；
- 查看 Tool、Permission、Harness 和 Evidence；
- v0.2 在 Plan、Build、Review 或高级 Agent 间工作。

### Gateway

v0.3 授权用户可以：

- 在飞书等平台选择 Workspace 和 Role；
- 恢复或继续 Session；
- 接收流式或聚合结果；
- 受到相同的 Permission 和 Workspace 约束。

## 7. 角色产品结构

### 核心角色

- Build；
- Plan；
- Review。

### 高级角色

v0.2 目标是让仓库现有其他角色可安装并按证据分级，不要求一次性全部 Stable。准确清单由审计从 Registry 和源码生成，不凭记忆补全。

### 发布标准

每个角色必须具备：

- 稳定 ID 和说明；
- Prompt；
- Tool/Skill 契约；
- 权限行为；
- 至少一个自动化场景；
- 当前成熟度和已知限制。

## 8. v0.3 Gateway 产品结构

- Gateway Core 目标 Stable。
- 飞书 Adapter 目标 Stable。
- 其他平台按证据分级。
- Gateway 进入宿主和插件产品链路，不复制整套业务语义。
- 具体调用方式由 v0.3 调用图和 Runtime API 审计后确定。

## 9. 核心用户流程

### 本地任务

```text
User
→ CLI/TUI
→ Host Session
→ Host Tool/Permission
→ Evidence
```

v0.2 接入后可在 Host Session 与 Host Tool/Permission 之间加入 Plugin Role/Orchestration。

### Gateway 任务（v0.3）

```text
Platform
→ Gateway Auth
→ Identity/Workspace
→ Host Session
→ Plugin Role/Orchestration
→ Host-governed Effects
→ Adapter Delivery
```

### Multi-Agent 任务（v0.2）

```text
Parent Task
→ Orchestrator
→ Subagent A / Subagent B
→ Parent-child State Mapping
→ Host-governed Tool Effects
→ Result Aggregation
```

## 10. 产品边界

v0.1 交付：独立 CLI/Host、DeepSeek Provider、一个默认 Agent、Session/Tool/Permission/Workspace、官方安装和共存。

v0.2 交付：Built-in Plugin、关键角色、Plan/Build/Review、Subagent/Multi-Agent Contract。

v0.3 交付：Gateway Core 和飞书 Stable。

所有版本都不承诺无监督高风险写入，也不因范围收窄而删除未经审计的插件 Runtime 代码。

## 11. 成功标准

- 用户感知为一个 DeepCode 产品。
- v0.1 可从官方制品安装且与 OpenCode/Oh-my-OpenAgent 共存。
- v0.2 插件能力可直接使用，无需额外安装。
- Host 和 Plugin 的职责清晰。
- Agent 编排能力被保留并有测试。
- 真实副作用受安全契约治理。
- v0.3 Gateway 与本地入口行为可解释、可追踪。
