# DeepCode v0.1 产品范围冻结

> 状态：Phase 0 已确认
> 分支：`develop`
> 决策日期：2026-07-27
> 目标版本：`v0.1.0`

## 1. 产品定义

DeepCode v0.1 是一款针对 DeepSeek 深度优化、内置多角色 Agent 系统、同时支持本地入口和消息平台入口的开源 Coding Agent。

产品由三个一级能力组成：

```text
DeepCode
├── DeepCode Runtime
│   ├── Session
│   ├── Provider
│   ├── Tool
│   ├── Permission
│   ├── Context
│   └── Harness
├── Built-in DeepAgent
│   ├── Role Registry
│   ├── Skill Registry
│   ├── Role Routing
│   ├── Planning
│   └── Review
└── DeepCode Gateway
    ├── Gateway Core
    ├── Platform Adapter
    ├── Authentication
    ├── Session Mapping
    ├── Workspace Policy
    └── Message Delivery
```

三者属于同一个 DeepCode 产品，不作为三个独立产品维护或发布。

## 2. 已确认的不可逆架构决策

### ADR-SCOPE-001 Gateway 进入 v0.1

- Gateway 是 v0.1 一级产品能力。
- Gateway Core 必须达到正式发布质量。
- 飞书作为第一个 Stable Adapter 目标。
- 其他 Adapter 按 Stable、Beta、Experimental 分级。
- Adapter 文件存在不等于平台已支持。

### ADR-SCOPE-002 oh-my-deepagent 正式内置

- `packages/oh-my-deepagent` 可以作为内部 Package 保留。
- 不作为独立产品、独立 CLI 或独立 npm 包发布。
- 13 个现有角色全部预装在 DeepCode 中，并要求达到正式交付质量。
- Role、Skill 和 Agent Policy 必须复用 DeepCode 的统一 Runtime。

### ADR-SCOPE-003 唯一生产 Runtime

CLI、TUI、Gateway 和 Built-in DeepAgent 必须进入同一套：

```text
Session + Provider + Context + Harness + Tool + Permission + History
```

禁止在 Gateway 或 oh-my-deepagent 中继续维护第二套生产 Session、Tool Loop、Permission、Memory 或 Provider 调用链。

### ADR-SCOPE-004 不以砍核心功能换取开源

v0.1 的收敛方式是：

- 删除重复架构。
- 修复不安全实现。
- 统一主链路。
- 建立测试和发布门禁。
- 对平台和模块进行成熟度分级。

不是删除 Gateway、Agent 系统或 Harness 研究成果。

## 3. v0.1 Must Have

### 3.1 DeepCode Runtime

1. 一种正式安装方式。
2. `deepcode --help`、`deepcode --version`、环境诊断。
3. DeepSeek OpenAI-compatible Provider。
4. Text、Reasoning、Tool Call、Tool Result、Usage 流式协议。
5. Workspace 识别和 Session 创建、恢复、中断。
6. Read、Search、Edit、Patch、Shell、Test 工具。
7. allow、ask、deny 权限链。
8. Workspace 边界、Symlink、Shell、Timeout、Abort 安全。
9. Context Compaction 和 Tool Continuation 正确。
10. Model Routing、Hard Constraints、Reasoning Lifecycle、Scope、Review 闭环。
11. 最终输出包含变更、验证证据、未验证项和风险。

### 3.2 Built-in DeepAgent

1. 13 个现有角色全部预装。
2. 默认角色为 Build。
3. Plan、Review 作为一级可见角色。
4. 其他角色进入高级角色区域，但不是外置插件。
5. 每个角色必须具有唯一 ID、Prompt、Tool 白名单、Skill 依赖、场景说明和风险等级。
6. 用户可以显式切换角色。
7. 角色切换不创建第二套 Session。
8. Role Tools、Skill Tools、Permission 和 Runtime Capability 必须取交集。
9. 每个角色至少具备单元测试和一个行为场景测试。
10. 至少 Build、Plan、Review、Oracle、Metis、Momus 完成真实 Runtime E2E；其他角色完成自动化场景 E2E 后方可标记 Stable。

### 3.3 Gateway

1. Gateway 默认关闭，默认只监听 localhost。
2. 公网模式必须显式启用。
3. 统一 Adapter Interface。
4. 入站签名或 Token 验证。
5. Timestamp、Replay、Idempotency、Body Limit、Rate Limit。
6. 多维 Session Key。
7. Workspace Allowlist 和 User Allowlist。
8. 有界 Queue。
9. 同 Session 保序，不同 Session 可并发。
10. 按 sourceAdapter 回复。
11. Gateway 直接调用统一 Runtime API。
12. 不允许每条消息启动 CLI 子进程作为正式执行方式。
13. 飞书 Adapter 达到 Stable。
14. 至少两个其他 Adapter 达到 Beta，候选为企业微信、Telegram、Slack。
15. 其余 Adapter 保留并清晰标记 Experimental。

### 3.4 开源工程

1. `bun run check` 单一质量门。
2. Runtime、Provider、DeepAgent、Gateway、安全、构建和安装 CI。
3. Secret、Dependency、License 扫描。
4. README、LICENSE、CONTRIBUTING、SECURITY、CODE_OF_CONDUCT、CHANGELOG、SUPPORT、UPSTREAM。
5. 干净环境安装矩阵。
6. 可重复的本地任务 Demo 和 Gateway Demo。

## 4. v0.1 Should Have

- Cache Usage 展示。
- 100 Turn Session 回归。
- Gateway 管理命令和连接诊断。
- Agent Role 决策和切换事件可观察。
- Harness Decision 调试视图。
- macOS/Linux Release Matrix。
- Windows Experimental 构建。

## 5. v0.1 非目标

以下不作为 v0.1 发布阻断：

- 云端托管和商业计费。
- 企业多租户、SSO 和组织管理后台。
- 分布式 Session Runtime。
- 完全自动多 Agent 并行调度。
- 动态生成并自动启用新角色。
- 自动修改全局 Skill。
- 所有 Gateway Adapter 同时达到 Stable。
- Desktop 专属 DeepCode 产品重设计。

## 6. 成熟度定义

### Stable

必须具备：

```text
PRD Requirement
+ Main Code Path
+ Applied Behavior
+ Automated Tests
+ Runtime Evidence
+ Security Review
+ User Documentation
```

### Beta

- 主要用户流程可用。
- 自动测试通过。
- 已知限制已记录。
- 不存在 P0 安全风险。
- 可能缺少多环境或长时间验证。

### Experimental

- 默认关闭或不影响主流程。
- 明确已知限制。
- 不得使用“正式支持”措辞。
- 不计入 v0.1 核心可用性承诺。

## 7. 角色发布规则

13 个角色全部预装，但每个角色仍需独立取得成熟度：

| 角色类别 | 产品展示 | v0.1 目标 |
|---|---|---|
| Build | 默认 | Stable |
| Plan | 一级入口 | Stable |
| Review | 一级入口 | Stable |
| Oracle / Metis / Momus | 高级角色 | Stable |
| Explore / Research / Debug | 高级角色 | Stable 或 Beta |
| Multimodal / Artistry 等 | 高级角色 | Beta；满足完整 E2E 后升级 Stable |

角色名称和实际仓库定义以 Role Registry 为准；Phase 1 开始前必须生成准确的 13 角色清单。

## 8. Gateway 平台发布规则

| 平台 | v0.1 目标 | 发布要求 |
|---|---|---|
| 飞书 | Stable | 鉴权、WS/HTTP、会话、回包、重连、真机 E2E |
| 企业微信 | Beta 候选 | 核心安全和多轮 E2E |
| Telegram | Beta 候选 | Secret Token、会话和回包 E2E |
| Slack | Beta 候选 | Signature、Timestamp、会话和回包 E2E |
| Matrix / Signal / WhatsApp / DingTalk / QQ / Email 等 | Experimental | 默认关闭、限制说明、不得冒充 Stable |

具体 Beta 选择由 Phase 4 的代码成熟度审计决定，但不得降低飞书 Stable 和 Gateway Core Stable 的目标。

## 9. 删除和保留原则

### 保留

- Gateway Core 和所有 Adapter 源码。
- oh-my-deepagent 的 Role、Skill、Prompt、Policy 和测试资产。
- 14 个 Harness 模块。
- OpenCode 原有 Runtime、UI 和扩展能力。

### 迁移后删除

- oh-my-deepagent 独立 Message Loop。
- oh-my-deepagent 独立 Session、Tool Executor、Permission、Memory、Provider 调用。
- Gateway 每条消息启动 CLI 子进程的正式路径。
- Gateway 固定第一个 Adapter 回包逻辑。
- 仅以 chatId 作为 Session Key 的逻辑。
- 无鉴权通用 Webhook 入队逻辑。
- 无界 Queue 和无法终止的子进程桥接。
- 各入口重复实现的权限和 Tool 安全特例。

### 仅修正文案，不删除能力

- 未经 E2E 前不宣称“11 平台全部稳定”。
- 未接入统一 Runtime 前不宣称“13 角色全部正式可用”。
- 未应用前不宣称“自动切换模型已完成”。
- 未形成 Enforcement 前不宣称“保证 Agent 不乱来”。

## 10. Go / No-Go

v0.1 发布必须满足：

1. 单一生产 Runtime。
2. 13 个角色全部预装且有自动测试；未达到 Stable 的角色必须明确标记 Beta，不得存在不可用角色。
3. Build、Plan、Review 和关键高级角色完成真实 Runtime E2E。
4. Gateway Core Stable。
5. 飞书 Adapter Stable。
6. 至少两个其他 Adapter 达到 Beta，或经产品决策记录批准降低为一个；不得隐式降低。
7. P0 安全问题为 0。
8. DeepSeek Provider Contract 全通过。
9. deny 不可绕过。
10. Gateway 不通过 CLI 子进程运行 Agent。
11. CI 全绿，安装矩阵通过。
12. README Claim Evidence Coverage 为 100%。
13. 至少 3 名外部用户完成本地 Coding Agent 任务。
14. 至少 3 名外部用户完成飞书 Gateway 任务。

## 11. 范围变更规则

本文件确认后，任何范围变更必须：

1. 新增 ADR。
2. 说明用户价值、维护成本、安全面和测试成本。
3. 更新 PRD、架构、测试计划和追踪矩阵。
4. 不得通过单个 Feature Commit 隐式扩大或缩小 v0.1 范围。
