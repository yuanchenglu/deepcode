## 1. 产品定义

DeepCode v0.1 Alpha 是针对 DeepSeek 优化、从 OpenCode 派生但与 OpenCode 用户状态隔离的开源 CLI Coding Agent。

```text
DeepCode v0.1 Alpha
├── Isolated CLI / Config / Data / Install Lifecycle
├── DeepSeek Provider
├── Host Session / Tool / Permission / Workspace
└── One Default Coding/Build Agent
```

目标架构仍包含 Built-in oh-my-deepagent、Gateway 和 Desktop，但它们不代表当前生产调用链，也不阻塞本版本。

## 2. 已确认的架构决策

### ADR-SCOPE-001 CLI-first Alpha

- 先交付一个最小、完整、可安装的本地用户闭环；
- 安装、共存、升级、卸载和官网 Smoke 是最前置门禁；
- 不以未集成的全量产品愿景阻塞真实用户验证。

### ADR-SCOPE-002 独立身份

- 默认使用 `deepcode` 命令、配置、数据、数据库和 `DEEPCODE_*`；
- 默认不得读取 `.opencode`、`opencode.json(c)`、`OPENCODE_*`；
- 不自动加载现有 Oh-my-OpenAgent；
- upgrade/uninstall 只处理 DeepCode。

### ADR-SCOPE-003 Host Runtime Governance

宿主对 Workspace 副作用、Permission、正式 Session/Task、Provider/Tool 审计、Context/History/Evidence 保持最终治理。

### ADR-SCOPE-004 Plugin Orchestration 保留为 v0.2 目标

正确原则仍是：

> **单一宿主执行边界，允许多个可组合的 Agent 编排循环。**

不预设删除 AgentRuntime、Message Loop、ToolRunner、MemoryStore、Provider、Transport、Subagent 或 Multi-Agent；v0.2 集成前先完成调用图、来源、许可证和 Contract 审计。

### ADR-SCOPE-005 Gateway 与 Desktop 后移

- Gateway Core/飞书 Stable 目标为 v0.3；
- Desktop 独立身份完成后单独发布；
- 两者不进入 v0.1 Alpha 默认制品或 Stable 主张。

## 3. v0.1 Must Have

### 3.1 Install/Release

- 本项目 GitHub Release Binary；
- 官网脚本校验 SHA-256；
- `deepcode --version`、`deepcode --help`；
- 安装、重复安装、升级、失败回滚、卸载；
- macOS/Linux 制品和 Required CI；
- SBOM、许可证清单、Secret/Dependency/License Scan。

### 3.2 Coexistence

- DeepCode 自有安装、配置、数据、缓存、状态、数据库和临时目录；
- 与 `opencode`、`omo` 同时安装和运行；
- 不读取或修改 OpenCode/Oh-my-OpenAgent 状态；
- Parallels VM-001~004 通过。

### 3.3 Host Runtime

- DeepSeek OpenAI-compatible Provider Contract；
- Session、Context、History；
- Tool Call/Result；
- Permission、Workspace、Shell、Timeout、Abort、Evidence；
- CLI/TUI 完成真实代码任务。

### 3.4 Default Agent/Harness

- 一个默认 Coding/Build Agent；
- `reasoning_effort` 正确 Applied；
- Model Routing 要么当前 Turn Applied，要么从 Alpha 主张移除；
- 不把日志记录冒充 Enforcement。

### 3.5 Open-source Governance

- DeepCode 自有 README、SECURITY、CONTRIBUTING；
- SUPPORT、UPSTREAM、CODE_OF_CONDUCT、第三方声明；
- README 主张与 Traceability 一致。

## 4. v0.1 非目标

- Gateway Core/飞书 Stable；
- 所有 Gateway Adapter；
- 13 个角色全部预装或 Stable；
- Plan → Build → Review、Parent/Subagent、Multi-Agent 正式交付；
- Desktop；
- npm 无作用域 `deepcode` / `deepcode-ai`；
- 云托管、计费、多租户、SSO；
- 无调用图证据的大规模 Runtime 删除。

## 5. 后续版本边界

### v0.2 Built-in Agent

- 正式 Host-Plugin 入口；
- 关键角色和 Skill；
- Plan → Build → Review；
- Subagent、权限继承、状态映射和 Evidence；
- 其余角色按证据分级。

### v0.3 Gateway

- Gateway Core Stable；
- 飞书 Stable；
- Auth/Replay/Idempotency/Workspace/有界 Queue；
- Gateway → Host → Plugin → Delivery E2E。

### Desktop

- 独立 App ID、协议、目录、更新源、签名、公证；
- 与 OpenCode Desktop 共存。

## 6. v0.1 Go/No-Go

- 官网安装源属于本项目；
- 发行身份与共存 Contract 通过；
- Alpha 暴露面 P0=0；
- Provider Contract 和本地任务 E2E 通过；
- Required CI、Release 和 Parallels VM Matrix 通过；
- 安装/升级/卸载不触碰 OpenCode；
- README Claim Evidence Coverage=100%。

## 7. 冻结结论

```text
隔离发行身份
→ 最小任务闭环
→ 可重建 Release
→ 共存验收
→ 官网公开 Alpha
→ Agent 编排
→ Gateway/飞书
→ Desktop
```

## 附录 B：Q&A 过程记录

#### Q#1：为何保留目标架构但收窄 v0.1？

> 2026-07-27 | 范围复核 | 用户确认

**问题**：插件、Gateway 和 Desktop 都有产品价值，但当前尚未形成经过验证的生产链。

**答案**：保留代码和目标架构，不把它们作为 v0.1 Alpha 门禁；用独立后续里程碑交付，避免误删，也避免阻塞上线。
