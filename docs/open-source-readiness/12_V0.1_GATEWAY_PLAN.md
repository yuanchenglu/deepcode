# DeepCode v0.1 Gateway 正式交付计划

> 状态：Phase 0 已确认
> 产品决策：Gateway 是 v0.1 一级能力，Gateway Core 目标 Stable，飞书 Adapter 目标 Stable

## 1. 目标

将现有多平台 Adapter 集合升级为安全、统一、可测试、直接调用 DeepCode Runtime 的正式 Gateway 产品能力。

正式链路：

```text
Platform
→ Adapter Auth
→ Parse / Normalize
→ Identity / Workspace Policy
→ Session Resolution
→ DeepCode Runtime
→ Runtime Events
→ Adapter Delivery
```

禁止链路：

```text
Platform
→ 无鉴权入队
→ 每条消息启动 CLI 子进程
→ 固定第一个 Adapter 回包
```

## 2. Gateway Core 范围

Gateway Core 必须提供：

1. Server 生命周期。
2. Adapter Registry。
3. Raw Body 获取。
4. 入站鉴权 Contract。
5. Timestamp 和 Replay Protection。
6. Idempotency。
7. Body Size 和 Rate Limit。
8. Message Normalization。
9. Identity Policy。
10. Workspace Allowlist。
11. Session Resolver。
12. 有界 Queue 和并发控制。
13. Runtime Bridge。
14. Response Aggregation。
15. Source Adapter Delivery。
16. Health、Metrics、Structured Logs。
17. Secret Redaction。
18. Graceful Shutdown。

## 3. 安全模型

### 3.1 默认安全

- Gateway 默认 disabled。
- 默认绑定 `127.0.0.1`。
- 公网绑定必须显式 `public: true`。
- 启用公网时必须通过配置检查：Adapter Auth、Workspace Allowlist、User Policy 均存在。
- 任一 Enforcement 组件初始化失败时 Gateway 拒绝启动。

### 3.2 入站鉴权

Adapter 必须在解析和入队前验证：

- Signature / Token。
- Timestamp Window。
- Nonce 或 Message ID。
- Body 完整性。
- Platform-specific verification challenge。

错误请求：

- 不进入 Queue。
- 不创建 Session。
- 不调用 Runtime。
- 日志不记录 Secret 或完整敏感正文。

### 3.3 Replay 和 Idempotency

- `(platform, tenant, messageId)` 唯一。
- 重复消息返回平台要求的 ACK，但不重复执行副作用。
- Idempotency Store 有 TTL 和容量控制。
- 进程重启后的行为按 Adapter 风险决定是否持久化。

### 3.4 Identity 和 Workspace

远程用户不能通过消息内容指定任意系统路径。

授权关系：

```text
Platform Identity
→ User Policy
→ Allowed Workspace
→ Permission Profile
→ Allowed Roles
```

## 4. Session 模型

Session Key 至少包含：

```text
platform
+ tenant
+ bot
+ user
+ chat
+ thread
+ workspace
```

要求：

- 不同平台同 chatId 不串话。
- 不同 Tenant 不串话。
- 私聊和群聊明确区分。
- Thread 支持的平台按 Thread 隔离。
- 同一远程会话可恢复 DeepCode Session。
- 用户可显式新建、继续、查看或结束 Session。

## 5. Queue 与并发

### 入站

- 有界 Queue。
- Queue Full 时拒绝或返回 busy。
- 单消息 Body 和 Attachment 大小限制。

### 执行

- 同 Session 串行。
- 不同 Session 并发，具有全局和 Adapter 上限。
- Runtime Abort 和 Timeout。
- 长任务支持状态消息或进度事件。

### 出站

- 平台速率限制。
- 消息长度分段。
- 重试采用指数退避。
- Send Result 持久化或记录 Evidence。

## 6. Runtime Bridge

Gateway 必须直接调用内部 `DeepCodeRuntime`：

```ts
runtime.prompt({
  sessionId,
  text,
  roleId,
  entrySource: "gateway",
  identity,
  abortSignal,
})
```

Gateway 不直接：

- 调用 Provider。
- 运行 Tool。
- 管理 Agent Message Loop。
- 实现独立 Permission。

迁移期 CLI 子进程桥可以短暂保留在显式 Legacy Flag 下，但：

- 默认关闭。
- 不进入正式测试通过标准。
- Runtime Bridge 完成后删除。

## 7. Adapter Contract

```ts
interface PlatformAdapter {
  name: PlatformName
  capabilities: AdapterCapabilities
  start(ctx: AdapterContext): Effect<void, GatewayError>
  stop(): Effect<void>
  verifyInbound(input: RawInbound): Effect<VerifiedInbound, AuthError>
  parse(input: VerifiedInbound): Effect<readonly GatewayMessage[], ParseError>
  send(input: OutboundMessage): Effect<SendResult, GatewayError>
  health(): Effect<AdapterHealth>
}
```

Capabilities 包括：

- webhook
- websocket
- thread
- attachments
- interactive approval
- message update
- streaming/progress
- max message length

Gateway Core 根据 Capability 降级 UX，不能假设所有平台能力一致。

## 8. 权限交互

### 支持交互组件的平台

展示：

- Tool。
- 命令或文件。
- 风险。
- once / always / reject。

### 不支持复杂交互的平台

- 高风险操作默认 reject 或暂停。
- 允许用户在本地客户端审批后继续。
- 不允许因平台限制自动 allow。

## 9. 平台成熟度矩阵

每个平台必须独立填写：

| 维度 | 说明 |
|---|---|
| Auth | 签名或 Token 正确执行 |
| Challenge | 平台验证握手 |
| Parser | 文本、群聊、私聊、批量事件 |
| Replay | 过期和重复拒绝 |
| Identity | tenant/user/chat/thread 提取 |
| Session | 多轮恢复和隔离 |
| Workspace | Allowlist 生效 |
| Permission | ask/deny 交互正确 |
| Outbound | 文本、分段、错误和重试 |
| Reconnect | WebSocket/长连接恢复 |
| E2E | Mock + 真机 |
| Docs | 配置和限制 |

## 10. v0.1 平台计划

### 飞书 Stable

必须完成：

- 官方 WebSocket 或 Webhook 协议。
- 应用认证。
- 事件解析。
- 私聊、群聊。
- Message ID 幂等。
- 多轮 Session。
- Workspace 和 User Allowlist。
- Role 选择。
- 文本回包和分段。
- 断线重连。
- Mock E2E。
- 真机 E2E。
- 安全测试。

### Beta 候选

企业微信、Telegram、Slack 中至少两个达到 Beta。

Beta 必须：

- Auth、Replay、Session、Workspace、Outbound、Mock E2E 完成。
- 不存在 P0。
- 已知限制明确。

### Experimental

Matrix、Signal、WhatsApp、DingTalk、QQ、Email 等现有 Adapter：

- 保留源码。
- 默认关闭。
- 未完成鉴权或 E2E 时不进入推荐配置。
- 按矩阵逐个平台升级。

## 12. 迁移里程碑

### G1 Core Contract

定义 Adapter、Message、Identity、Session、Delivery 类型。

### G2 Security Middleware

实现 Auth、Replay、Idempotency、Limit。

### G3 Runtime Bridge

接入统一 Runtime，保留 Legacy Flag 作为短期回退。

### G4 Queue / Session

实现有界 Queue、多维 Key、保序与并发。

### G5 Feishu Stable

完成飞书 Mock 和真机 E2E。

### G6 Beta Adapters

选择两个成熟度最高的平台补齐。

### G7 Legacy Removal

删除 CLI 子进程桥、首 Adapter 回包、chatId-only Session 和无鉴权路径。

## 13. 退出条件

1. Gateway 默认关闭且默认 localhost。
2. 所有入站请求先鉴权后入队。
3. Gateway 直接调用统一 Runtime。
4. 无 CLI 子进程正式路径。
5. Session 无跨平台、跨租户串话。
6. Workspace Allowlist 不可绕过。
7. Queue、Timeout、Abort 有界。
8. 按 sourceAdapter 回包。
9. 飞书 Stable 矩阵全通过。
10. 至少两个其他 Adapter 达到 Beta，或具有显式产品变更决策。
11. Gateway Security CI 为 Required Check。
